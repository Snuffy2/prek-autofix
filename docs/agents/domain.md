# Domain docs

This repository has one domain context across collect, apply, and shared code.
Keep the glossary in root `GLOSSARY.md` and architecture decision records (ADRs)
in `docs/adr/`.

Before exploring the code, read the glossary and the ADRs relevant to the work.
If either is absent, continue. Use the domain-modeling skill to create them when
a term or decision is agreed.

Use glossary terms in issues, proposals, and tests. Surface any conflict with an
existing ADR and explain why the decision should be revisited.
